# Issue tracker: Gitea

本仓库的 issue 和 PRD 记录在 Gitea Issues 中。

- **仓库 slug**：`luis/PrivLink`（canonical，与 `git remote -v` 一致）
- **服务器**：由 helper 脚本从 tea 配置（`.tea-config/tea/config.yml` 或
  `~/.config/tea/config.yml`）自动发现（私有部署地址不在仓库中记录）
- **访问方式**：使用 `gitea-issues` skill —— 通过 `curl.exe --noproxy "*"`
  调用 Gitea REST API。不要使用 `tea` CLI（此环境下有代理/SSL 握手问题）。

## 约定（通过 gitea-issues skill 的 helper 函数）

先按 gitea-issues skill 的 Setup 一节 dot-source `gitea-api.ps1`，然后：

- **创建 issue**：`New-GiteaIssue -Title "..." -Description "..." [-Labels "..."]`
- **读取 issue**：`Get-GiteaIssue -Number <n>`，评论用 `Get-GiteaIssueComments -Number <n>`
- **列出 issue**：`Get-GiteaIssues -State open`
- **评论**：`Add-GiteaComment -Number <n> -Message "..."`
- **加标签 / 删标签**：`Set-GiteaLabels -Number <n> -Labels "..."` /
  `Remove-GiteaLabel -Number <n> -LabelId <id>`（ID 从 `Get-GiteaLabels` 获取）
- **关闭**：先 `Add-GiteaComment` 写关闭说明，再 `Close-GiteaIssue -Number <n>`

标签按**名称**指定（helper 自动解析为 ID）。AI 在 triage 中产生的 issue
评论，开头须加一行：`> *This was generated by AI during triage.*`

## Pull requests as a request surface

**PRs as a request surface: no.** _（若本仓库将外部 PR 视为功能请求纳入
triage，把此处改为 `yes`。）_

## 当 skill 说 "publish to the issue tracker"

创建一个 Gitea issue（`New-GiteaIssue`）。

## 当 skill 说 "fetch the relevant ticket"

运行 `Get-GiteaIssue -Number <n>` 并附带 `Get-GiteaIssueComments -Number <n>`。
